Getting Started

One guided pass over everything this app can do — required cluster basics first, then optional features you can enable or skip. Nothing here does anything you can't already do from the individual tabs; this just puts it all in one place with the required .env variables filled in for you instead of hand-edited.

1 Pi-hole Cluster

The Pi-hole node IPs this app manages, plus the Pi-hole v6 admin password used to authenticate against every node's API.

2 SSH Trust

Distributes this app's SSH key to every node above so it can push DHCP config and reload DNS. Safe to re-run any time.

3 VIP & DHCP Failover (optional)

If a keepalived VIP already sits in front of the cluster for DNS, set it here so the Failover tab can keep DHCP active on only the current VIP master. Leave blank if there's no VIP.

4 External DHCP Source (optional, UniFi only)

For setups where Pi-hole handles DNS only and DHCP is served by UniFi — pulls the client name/MAC/IP list from a UniFi OS controller so devices don't show up as "Unknown." Leave source blank to disable.

5 Notifications (optional)

A generic webhook — works with Home Assistant's REST API, ntfy, a Telegram bridge, n8n, or anything else that takes a webhook. Fires on a node left down, a gravity partial-failure, an upgrade failure, or a failed post-upgrade health check. Leave blank to disable.

6 NetBox Import (optional)

Read-only import of VLANs and static host reservations from NetBox's IPAM+DCIM (Setup tab, once configured). Leave URL blank to disable.

7 Admin Login (optional)

Off by default — every page and API call is open to anyone who can reach this app. Turning this on requires a password afterward (session-based, no restart needed).
