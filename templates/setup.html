Setup

Admin Login

Off by default — anyone who can reach this app's URL can use it with no login at all. Turning this on requires a password for every page and API call (session-based, so you only log in once per browser). The password is saved back into this stack's own .env (ADMIN_PASSWORD), same as the SSH key above — not just the /data volume.

Fleet Nodes

The Pi-hole node IPs every feature in this app operates on. Seeded once from PIHOLE_IPS on first boot; after that, this list (not the env var) is authoritative — adding or removing a node here takes effect immediately across every loop (health monitor, replication, updater, gravity, failover), no restart needed.

Pi-hole SSH Trust

Distributes this app's SSH key to every configured Pi-hole node so it can push dnsmasq config and reload DNS. Safe to re-run any time — existing trust is left alone, and only nodes that don't already have this key get updated. The target account (PIHOLE_SSH_USER) doesn't need to be root — a non-root account with passwordless sudo works too, and is required on nodes where root only allows key-based login.

Private Key (base64)

Already saved to the persistent /data volume — this app will keep using it across restarts with no further action. It's also just been written back into this stack's own .env on the host (PIHOLE_SSH_KEY_B64), so it survives even that volume being lost. Copy this only if you want to reuse the same key in a different deployment's .env.

Import Existing Scopes

Reads back whatever's already deployed at /etc/dnsmasq.d/ on a node — useful for picking up VLANs pushed there by another instance (e.g. before a migration) that aren't in this instance's local store yet — plus the node's own standard Pi-hole scope and its static DHCP reservations, for a full picture of what's already configured there.

Import from NetBox

Reads VLANs and their associated Prefixes from NetBox's IPAM, plus every IP Address in that prefix that's assigned to a device/VM interface with a MAC address, as candidate static host reservations. Gateway and the DHCP-issuable range aren't modeled in NetBox, so both are a best-effort guess — review and edit on the VLANs page after import. Read-only against NetBox; requires NETBOX_URL and NETBOX_TOKEN to be set. Inert otherwise.

External DHCP-Source Sync

For setups where Pi-hole handles DNS only and DHCP is actually served by a different platform (UniFi, pfSense, OPNsense) — Pi-hole never sees a lease in that topology, so every client shows up as "Unknown". If configured (EXTERNAL_DHCP_SOURCE + the matching credentials env vars), this pulls the client name/MAC/IP list from that platform and publishes it as local DNS records on every node, same as this app already does for its own VLAN-managed DHCP. Currently only a UniFi OS controller is implemented, and it hasn't been exercised against real UniFi hardware yet — treat it as best-effort. Inert (does nothing) unless explicitly configured.
