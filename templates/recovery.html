Recovery

Clones a healthy node's settings, DHCP static reservations, groups & client group assignments, and VLAN dnsmasq.d scopes onto a target node — then triggers a gravity update on the target. Use this after reprovisioning a wiped/replaced node, instead of restoring from a Teleporter backup (Teleporter only exports settings, not the full gravity/query databases, so it's a poor fit for actually rebuilding a node).

This overwrites the target node's settings, DHCP reservations, groups, and client assignments with the source's — there's no merge, no recency comparison, and no undo. Only run this against a node you intend to fully replace with another's state (a fresh/wiped node, typically).
